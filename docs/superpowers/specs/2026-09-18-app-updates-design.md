# App Updates — Design

Date: 2026-09-18
Status: Approved

## Purpose

Ascend is built from source and ad-hoc signed; nothing tells an installed copy that a
newer one exists. This adds update checking: the app looks for a new release on its own,
tells the user, and installs it only after the user says yes.

## Decisions

| Decision | Choice |
|---|---|
| Mechanism | Sparkle 2 via Swift Package Manager |
| Consent | Notify, then wait — no unattended downloads or installs (`SUAutomaticallyUpdate` off) |
| Release host | Public GitHub repo `Duarte0903/Ascend`: zip on GitHub Releases, `appcast.xml` on `main` |
| Feed URL | `https://raw.githubusercontent.com/Duarte0903/Ascend/main/appcast.xml` |
| Update integrity | EdDSA signature on the zip; private key in the login Keychain, public key in Info.plist |
| Code signing | Stays ad-hoc. Sparkle accepts an update on the EdDSA signature alone and clears quarantine after install, so no Developer ID and no notarisation |
| Release flow | One local script, `scripts/release.sh <version>`, run once per release. No CI |
| Version source | `project.yml` only; Info.plist reads `$(MARKETING_VERSION)` / `$(CURRENT_PROJECT_VERSION)` |
| Check cadence | A quiet check 3 s after launch and every 24 h while open, surfaced as a toast; plus **Ascend ▸ Check for Updates…** |

## In the app

### Dependency

`project.yml` gains a package `Sparkle` (`https://github.com/sparkle-project/Sparkle`,
major version 2) linked to the `Ascend` target. `scripts/build.sh` already runs
`codesign --force --deep --sign -` over the built app, which re-signs the embedded
`Sparkle.framework` and its helpers ad-hoc along with everything else. Sandbox stays off,
so Sparkle runs its installer in-process and needs no XPC services.

### Info.plist

| Key | Value | Why |
|---|---|---|
| `CFBundleShortVersionString` | `$(MARKETING_VERSION)` | one place to bump |
| `CFBundleVersion` | `$(CURRENT_PROJECT_VERSION)` | Sparkle compares this number |
| `SUFeedURL` | feed URL above | where to look |
| `SUPublicEDKey` | public key from `generate_keys` | verifies the zip |
| `SUEnableAutomaticChecks` | `false` | present so Sparkle never asks; `UpdateService` runs the checks itself |
| `SUAutomaticallyUpdate` | `false` | the user approves every install |

`Sources/Ascend/Resources/Info.plist` is generated by xcodegen from `info.properties`
in `project.yml`, so every key above is set there; the literal
`CFBundleShortVersionString: "1.0"` becomes `$(MARKETING_VERSION)`.

### `Services/UpdateService.swift`

An `@Observable @MainActor final class UpdateService: NSObject` that owns one
`SPUStandardUpdaterController(startingUpdater: true, updaterDelegate: self,
userDriverDelegate: nil)` and acts as its `SPUUpdaterDelegate`. It exposes:

- `func checkForUpdates()` — forwards to the controller. Manual checks always show a
  result (either the update window or Sparkle's "you're up to date" / "can't connect"
  alert).
- `var canCheckForUpdates: Bool` — mirrors `SPUUpdater.canCheckForUpdates` through KVO
  so the menu item disables itself while a check or install is in flight.
- `var availableUpdate: AvailableUpdate?` — set by the quiet check
  (`SPUUpdater.checkForUpdateInformation()`, no UI) 3 s after launch and every 24 h
  after; cleared when the user dismisses the toast, skips the version, or installs.
- `func dismissAvailableUpdate()`.

`Views/Components/UpdateCard.swift` is the toast: overlaid at the top centre of the
window by `RootView`, it drops in as an accent circle with a white arrow, pauses
0.7 s, then springs into a 360 pt strip (icon, title, version, **Update…**, ×).
**Update…** calls `checkForUpdates()`, so approval still happens in Sparkle's window.

`AscendApp` holds it as `@State` and adds one command:

```swift
CommandGroup(after: .appInfo) {
    Button("Check for Updates…") { updates.checkForUpdates() }
        .disabled(!updates.canCheckForUpdates)
}
```

Sparkle's standard windows do the rest of the UI: the "Ascend 1.1 is available"
sheet with release notes and **Install Update / Remind Me Later / Skip This Version**,
the download progress, and the relaunch.

## Releasing

### `scripts/release.sh <version> [-m "notes"] [--dry-run]`

Written once; run once per release with the new version number.

1. **Bump.** Sets `MARKETING_VERSION` to `<version>` and increments
   `CURRENT_PROJECT_VERSION` in `project.yml`. Refuses if `<version>` equals the current
   marketing version.
2. **Build.** Runs `scripts/build.sh` (xcodegen → xcodebuild Release → ad-hoc sign).
3. **Package.** `ditto -c -k --sequesterRsrc --keepParent` the app to
   `build/release/Ascend-<version>.zip`.
4. **Sign.** `sign_update` on the zip, private key from the login Keychain. Output is
   the `sparkle:edSignature` and `length` attributes.
5. **Appcast.** Prepends one `<item>` to `appcast.xml` at the repo root (creating the
   file if absent):
   - `<title>` = version, `<pubDate>` = now (RFC 822)
   - `<sparkle:version>` = build number, `<sparkle:shortVersionString>` = version
   - `<sparkle:minimumSystemVersion>` = `26.0`
   - `<description>` = the `-m` text, HTML-escaped, when given
   - `<enclosure url="https://github.com/Duarte0903/Ascend/releases/download/v<version>/Ascend-<version>.zip" length=… type="application/octet-stream" sparkle:edSignature=…/>`
6. **Hand-off.** Prints the steps it will not perform, in this order:
   1. create GitHub Release `v<version>` and attach the zip (a ready-to-run
      `gh release create` line is printed);
   2. commit `project.yml` and `appcast.xml`;
   3. push.

   The order matters: if the appcast lands before the zip does, every installed app
   sees a 404 on its next check.

`--dry-run` stops after step 5 and leaves `appcast.xml` written, so the output can be
inspected without a release. It still bumps `project.yml`; the printed hand-off says
so.

### One-time setup

- Sparkle's command-line tools (`generate_keys`, `sign_update`) ship inside the SPM
  artifact at `build/SourcePackages/artifacts/sparkle/Sparkle/bin/`; `release.sh`
  builds once to resolve the package if that directory is missing.
- If the Keychain has no Sparkle key, `release.sh` runs `generate_keys`, prints the
  public key, and stops so it can be pasted into Info.plist as `SUPublicEDKey`
  before the first release is built. The private key never leaves the Keychain and
  is never committed.

## Failure modes

| Situation | Behaviour |
|---|---|
| Offline, feed unreachable, raw.githubusercontent cache stale | Scheduled check fails silently and retries next interval; manual check shows Sparkle's connection alert |
| Zip missing (release created without the asset) | Download fails; Sparkle reports it; nothing is replaced |
| Signature mismatch or tampered zip | Sparkle refuses the update before extraction |
| Update installed over an ad-hoc signed app | Accepted on EdDSA; quarantine released; relaunches with no Gatekeeper prompt |
| Running a dev build from `build/` | It checks the real feed too. Installing would replace the copy in `build/`, not `/Applications`. Acceptable |
| User picks Skip This Version | Sparkle remembers; that version is not offered again |

## Testing

- `Tests/AscendTests/UpdateConfigurationTests.swift` reads the built bundle's Info.plist
  and pins: `SUFeedURL` is the feed URL above; `SUPublicEDKey` is non-empty;
  `SUAutomaticallyUpdate` is `false`; `SUEnableAutomaticChecks` is `true`;
  `CFBundleVersion` is an integer and `CFBundleShortVersionString` is non-empty.
  A future edit cannot silently turn on unattended installs.
- `release.sh --dry-run` exercised once by hand; the resulting `appcast.xml` is
  validated as well-formed XML and checked for the expected enclosure URL.
- End-to-end, once: a dev build with a lower version pointed at a local
  `file://` appcast referencing the release zip, to confirm Sparkle installs over an
  ad-hoc signed bundle and relaunches without a Gatekeeper prompt. The feed
  override is made by editing `SUFeedURL` in a built copy's Info.plist and
  re-signing that copy — never in the source tree. Sparkle refuses `file://` feeds,
  so the local feed is served over `http://127.0.0.1` with
  `NSAllowsLocalNetworking` added to that copy only. **Done 2026-09-18: passed.**

## Out of scope

- CI-built releases.
- Delta updates.
- A settings toggle for the check cadence. `Skip This Version` and Sparkle's defaults
  cover the cases that matter.
